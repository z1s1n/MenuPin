# 原生列表重排设计 · 2026-10-03

用户已认可苹果官方原生 List + onMove 方案。保留现有图钉、搜索、分组和更多菜单，替换 ScrollView/VStack + 自定义文本拖放。

采用系统列表拖动和插入位置反馈，在 macOS 15.6.1 原生演示中验证，不能将 macOS 27 新重排 API 的动画效果当作当前系统已实现。

List 回调只在松手后把源下标和落点转为同组真实图标前/后锚点。只接受单项目；原位置不提交；搜索、扫描、忙碌、未知分组和无可靠身份的项目禁止列表拖动。接收时核对分组快照与项目引用。

松手后立即给出面板的预期顺序，保持真实扫描结果独立；系统移动确认成功才保存；失败显示实际顺序并回退预览。拖动取消不产生移动回调，不改系统位置。遵守减少动态效果设置。

辅助功能、收起策略和第三方菜单打开机制不改动。验证范围必须区分原生 UI 与真实第三方控制；新版安装后检查进程版本和权限，不自动授予权限。

实机验证发现：macOS 15 的 List 行内主按钮会截获名称区域拖动，普通和 simultaneous 点击手势也阻止该区域触发 onMove。保留原生按钮及单击打开能力，明确使用左侧 ≡ 拖拽柄。已验证柄的上下移动；不声称名称区域可拖动。没有引入 macOS 27 API。
